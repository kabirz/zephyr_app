## 一、Gateway UDP 配置协议改动

### 1.1 默认参数变更

| 参数 | 旧默认值 | 新默认值 | 说明 |
|------|---------|---------|------|
| 设备 IP (静态) | `192.168.11.220` | **`192.168.11.100`** | 设备本机地址 |
| 配置端口 | `8601` | **`8600`** | 所有配置命令 + 固件升级走此端口 |
| 数据端口 | `9600` | `9600` (不变) | nRF24↔上位机数据透传 |
| 上位机 IP | `192.168.11.100` | **`192.168.11.150`** | nRF24 数据转发目标 |
| 上位机接收端口 | `8602` | **`9602`** | nRF24 数据转发目标端口 |

> ⚠️ 旧默认上位机 IP (`192.168.11.100`) 与新设备 IP 撞号,已拆开。

### 1.2 业务命令重新编号 (从 0x10 起)

所有业务命令 ID 已重新分配。**旧 ID 全部失效**。

| 新 ID | 命令 | 旧 ID | 帧格式 (请求) | 帧格式 (回复) | 说明 |
|-------|------|-------|-------------|-------------|------|
| **0x10** | SET_IP | 0x12 (SET_NET) | `[0x10][ip 4B]` | `[0x10][1B: 1=成功/0=失败]` | 设置静态 IP,带校验 |
| **0x11** | GET_NET | 0x13 | `[0x11]` | `[0x11][data_port 2B][host_ip 4B][host_port 2B]` = 9B | 查询网络参数 |
| **0x12** | SET_RF24 | 0x14 | `[0x12][addr 5B]` | `[0x12][addr 5B]` = 6B | 设置 nRF24 地址 (**信道已移除**) |
| **0x13** | GET_RF24 | 0x15 | `[0x13]` | `[0x13][addr 5B]` = 6B | 查询 nRF24 地址 (**信道已移除**) |
| **0x14** | SET_HOST | 0x18 | `[0x14][host_ip 4B][port 2B]` | `[0x14][host_ip 4B][port 2B]` = 7B | 设置数据转发目标 |
| **0x15** | DISCOVER | 0x20 | `[0x15]` | `[0x15][ip 4B][config_port 2B]` = 7B | 广播发现 |

#### 移除的命令 (不再支持)

| 旧 ID | 命令 | 原因 |
|-------|------|------|
| 0x14 (旧) | SET_RF24 中的信道字段 | 信道固定为 1 |
| 0x16 | SET_NET_MODE | DHCP 模式切换移除 (仍可用 shell 配,但无远程命令) |
| 0x17 | GET_NET_MODE | 同上 |
| 0x19 | GET_HOST | GET_NET 已包含 host 信息,冗余移除 |

### 1.3 关键命令详解

#### SET_IP (0x10) —— 设置静态 IP

```
请求: [0x10][ip 4B BE]                    共 5 字节
回复: [0x10][1B: 1=成功 / 0=失败]         共 2 字节
```

- **IP 有效性校验** (新版新增):拒绝以下地址,回复 `0`:
  - `0.0.0.0`
  - 环回 `127.x.x.x`
  - 组播 `224.x.x.x` – `239.x.x.x`
  - 广播 `255.255.255.255`
  - 保留 `240.x.x.x` – `255.x.x.x`
- **DHCP 模式拒绝**:设备处于 DHCP 模式时,SET_IP 回复 `0`(IP 由 DHCP 分配)
- 持久化,需**重启生效**
- 静态模式掩码固定 `255.255.255.0`,网关 = IP 末段改 1 (如 `192.168.11.100` → `192.168.11.1`)

#### GET_NET (0x11) —— 查询网络参数

```
请求: [0x11]                                        共 1 字节
回复: [0x11][data_port 2B][host_ip 4B][host_port 2B] 共 9 字节
```

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| data_port | 1-2 | 2B BE | 数据端口 |
| host_ip | 3-6 | 4B BE | nRF24 数据转发目标 IP |
| host_port | 7-8 | 2B BE | nRF24 数据转发目标端口 |

> 配置端口**不在**此响应中。用 DISCOVER (0x15) 获取配置端口。

#### DISCOVER (0x15) —— 广播发现 (新命令)

```
请求: [0x15]                                共 1 字节
回复: [0x15][ip 4B][config_port 2B]         共 7 字节
```

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| ip | 1-4 | 4B BE | 设备 IP (取自 live interface) |
| config_port | 5-6 | 2B BE | 配置端口 |

**使用流程**:
1. 上位机向 `255.255.255.255:8600` 广播 `[0x15]`
2. 设备回复 `[ip][config_port]`
3. 上位机据此定向单播后续命令

#### SET_RF24 / GET_RF24 (0x12 / 0x13) —— 仅地址

```
SET_RF24 请求: [0x12][addr 5B]   共 6 字节    回复: 同
GET_RF24 请求: [0x13]            共 1 字节    回复: [0x13][addr 5B] 共 6 字节
```

> ⚠️ **信道字段已移除**。旧格式 `[ch 1B][addr 5B]` 不再有效。信道固定为 1,不可配。

### 1.4 广播放行规则变更

| 旧规则 | 新规则 |
|--------|--------|
| GET_NET / SET_NET 允许跨子网广播 | **仅 DISCOVER 允许**跨子网广播 |

上位机必须先 DISCOVER 拿到设备 IP,再**定向单播**其他命令。跨子网广播其他命令会被设备静默丢弃。

### 1.5 固件升级命令 (0x01-0x05,不变)

固件升级命令 ID 和帧格式**未变**,但版本查询回复格式变了(见第三节)。

## 二、mod_handler CAN 配置协议改动

### 2.1 RF24 配置命令 (0x110 / 0x111)

#### RF24_CONFIG_CMD (0x110) —— 平台 → 手柄

| 子命令 | 旧 | 新 |
|--------|-----|-----|
| `0x01` SET_CHANNEL | ✅ 设置信道 | ❌ **已移除** |
| `0x02` GET_CONFIG | ✅ 查询配置 | ✅ 查询地址 (信道固定不返回) |

> 平台不再能远程设置信道。信道固定为 1。地址只能通过手柄 shell `rf24 addr` 本地设置。

#### RF24_CONFIG_RESP (0x111) —— 手柄 → 平台

```
旧: [cmd 1B][channel 1B][addr 5B][reserved 1B]   共 8 字节
新: [cmd 1B][addr 5B][reserved 2B]               共 8 字节 (信道固定1,不返回)
```

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| cmd | 0 | 1B | 子命令码 (0x02) |
| addr | 1-5 | 5B | nRF24 地址 |
| reserved | 6-7 | 2B | 保留 (0) |

### 2.2 CAN 固件升级帧 ID 总览 (更新后)

| 帧 ID | 方向 | 用途 |
|-------|------|------|
| 0x101 | 平台 → 手柄 | 控制命令 (START_UPDATE/CONFIRM/VERSION/REBOOT) |
| 0x102 | 手柄 → 平台 | 响应帧 (code + offset) |
| 0x103 | 平台 → 手柄 | 固件数据 |
| 0x104 | 平台 → 手柄 | keyhash 分帧 (5 帧) |
| **0x105** | **手柄 → 平台** | **版本字符串分帧 (新增)** |

## 三、固件版本查询改动 (UDP + CAN)

### 3.1 新版本字符串格式

```
v<M>.<m>.<p>_<6hex>
```

- `<M>.<m>.<p>` 来自 VERSION 文件 (MAJOR.MINOR.PATCH),**不含** EXTRAVERSION
- `<6hex>` 是 git commit hash 前 6 位 (编译期注入)
- 示例: `v0.1.0_0b4ee3`、`v0.1.4_0b4ee3`

> 旧格式 `"0.1.0-dev"` (UDP) 和 `0x00010100` 整数 (CAN) 均已废弃。

### 3.2 UDP GET_VERSION (0x04) —— gateway

```
请求: [0x04]
回复: [0x04][版本字符串, 变长, 无末尾 '\0']
      示例: [0x04]v0.1.0_0b4ee3
```

无结构性变化,只是字符串内容格式改了。

### 3.3 CAN VERSION 查询 —— mod_handler (破坏性变更)

**旧协议** (单帧整数):
```
平台发 0x101 cmd=VERSION(2)
手柄回 0x102: code=VERSION(2), offset=APPVERSION(0x00010100)
```

**新协议** (首帧 + 多帧字符串):
```
平台发 0x101 cmd=VERSION(2)
手柄回 0x102: code=VERSION(2), offset=字符串总长度 (如 15)
手柄随后发 N 帧 0x105:
  [seq 1B][text 7B]  (末帧不足 7B 用 '\0' 填充)
```

#### 0x105 版本字符串帧格式

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| seq | 0 | 1B | 序号 (从 0 开始) |
| text | 1-7 | 最多 7B | 版本字符串片段 |

**上位机拼接逻辑**:
1. 收到 0x102 code=VERSION,记录 `offset` = 字符串总字节数
2. 收集后续 0x105 帧,按 `seq` 排序
3. 拼接所有 `text` 字段,或遇 `'\0'` 截断
4. 得到完整版本字符串,如 `v0.1.4_0b4ee3`

**示例** (字符串 `v0.1.4_0b4ee3`, 长度 15 字节):
```
0x102: code=2, offset=15
0x105 seq=0: "v0.1.4_0"     (7 字节)
0x105 seq=1: "b4ee3\0\0"    (5 字节 + 2 字节 '\0' 填充)
```

## 四、固定参数变更

| 参数 | 旧 | 新 | 影响范围 |
|------|-----|-----|---------|
| nRF24 信道 | 可配 (0-125) | **固定 1** | gateway + mod_handler |
| 子网掩码 (静态) | 固定 /24 | 固定 /24 (不变) | — |
| 网关 (静态) | IP 末段改 1 | IP 末段改 1 (不变) | — |

nRF24 信道在**两端**(gateway 和 mod_handler)都固定为 1,不可通过任何远程命令或 shell 修改。地址仍可配(两端必须一致才能通信)。

## 六、协议帧格式速查 (新)

### Gateway UDP 配置端口 (8600)

```
命令帧: [cmd 1B][data...]          (无魔数头)
数据帧: [帧ID 2B BE][payload]      (走数据端口 9600)
```

| cmd | 名称 | 请求 | 回复 |
|-----|------|------|------|
| 0x01 | FW_START | `[size 4B LE][keyhash 32B?]` | `[1B status]` |
| 0x02 | FW_DATA | `[data ≤511B]` | `[offset 4B LE]` |
| 0x03 | FW_END | `[test 1B][crc 2B LE]` | `[1B result]` |
| 0x04 | GET_VERSION | (空) | `[版本字符串]` (如 `v0.1.0_0b4ee3`) |
| 0x05 | REBOOT | (空) | (空) |
| 0x10 | SET_IP | `[ip 4B]` | `[1B: 1/0]` |
| 0x11 | GET_NET | (空) | `[data_port 2B][host_ip 4B][host_port 2B]` |
| 0x12 | SET_RF24 | `[addr 5B]` | `[addr 5B]` |
| 0x13 | GET_RF24 | (空) | `[addr 5B]` |
| 0x14 | SET_HOST | `[host_ip 4B][port 2B]` | `[host_ip 4B][port 2B]` |
| 0x15 | DISCOVER | (空) | `[ip 4B][config_port 2B]` |

> 多字节整数均为**大端序 (Big-Endian)**。

### Mod_handler CAN 帧

| 帧 ID | 方向 | 用途 |
|-------|------|------|
| 0x101 | 平台→手柄 | `[cmd 4B LE][val 4B LE]` (cmd: 0=START 1=CONFIRM 2=VERSION 3=REBOOT) |
| 0x102 | 手柄→平台 | `[code 4B LE][offset 4B LE]` (VERSION 时 offset=字符串长度) |
| 0x103 | 平台→手柄 | 固件数据 8B |
| 0x104 | 平台→手柄 | keyhash: `[seq 1B][chunk 7B]` × 5帧 |
| 0x105 | 手柄→平台 | 版本字符串: `[seq 1B][text 7B]` × N帧 |
| 0x110 | 平台→手柄 | RF24 配置: `[cmd 1B]` (cmd: 2=GET_CONFIG) |
| 0x111 | 手柄→平台 | RF24 配置响应: `[cmd 1B][addr 5B][reserved 2B]` |
| 0x763 | 手柄→平台 | 心跳 |
| 0x1E3 | 手柄→平台 | 手柄状态 |
| 0x263 | 平台→手柄 | 超欠挖+激光 |
| 0x363 | 平台→手柄 | X/Y 坐标 |
| 0x463 | 平台→手柄 | Z 坐标 |
